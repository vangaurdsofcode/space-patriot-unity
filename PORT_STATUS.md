# Space Patriot Unity restoration

This is an incomplete port. The initial Unity prototype dropped substantial parts of the original game and is not a completed or fully playable remake. Original source, documentation and art are retained in `Reference/Original`; original artwork is also imported under `Assets/SpacePatriot/Original`.

The direction remains grounded industrial science fiction, a Unity project targeting Windows PC, premium with no in-game purchases. Preserving the original design and systems is required. The ten industrial chassis refits are a first revision; the full visual redesign remains unfinished. See ENGINE_INTEGRATION.md for the engine-by-engine implementation status.

Latest verified work (26 September): grass, forest and Gaussian foliage now share spherical cells, global climate sampling, radial roots and planet-relative orientation. The 2.7 km port cap is removed. Actual Unity checks passed at equatorial and southern sites on Earth and TRAPPIST-1 e, including revisits, seams, world switches, transformed planets and altitude gates. Near grass retains at most nine tiles/108,000 blades; full trees are capped at 2,000; distant splat layers are also bounded and culled. [Results and captures](ArtDirection/spherical-vegetation-results.md) document the remaining synchronous cell-selection cost. A subsequent [radial-sky pass](ArtDirection/radial-sky-results.md) replaced the fixed world-Y horizon; twelve live GPU captures cover multiple latitudes and ascent. Terrain LOD, cloud and lighting transitions still need work.

Cockpit physical-display clicks now open their corresponding menus, and rotary changes reveal the affected page. [31 live raycast checks](Validation/cockpit-mfd-menu-runtime.txt) passed; screen glyphs were enlarged and footer hints shortened for readability. The cockpit model still needs work, including a gray upper area seen in the capture whose source has not yet been identified.

The original standalone Grassworks demo's fireflies now use bounded circular yellow-green sprites, near-camera fading and independent pulses. [Eight actual browser GPU checks](Validation/grassworks-firefly-gpu.json) passed, including 120 overlapping insects without white pixels. This is a fix to the original engine demo; it is not a claim that native Unity fireflies are implemented.

The Kestrel six-view bake had a separate persistence defect: each saved blend retained the original packed atlas, invalidating the previous preservation-only check. The repaired six-view pipeline explicitly replaces packed PNG bytes, registers source foreground without image margins, corrects UV gutters, removes old hull UV layers, and neutralizes incompatible old hull PBR maps. Independent reopening of all six passes verifies real target-pixel changes and protected earlier views; Unity imported the sole UV0 on all three hull LODs. This fixes bake data flow, not final art quality: faceted seams, wing/drive detail and a disconnected forward landing leg remain visible. The [fleet inventory](ArtDirection/fleet-mesh-port-inventory.json) records the ten original gameplay families / 100 variants, which retain their existing exterior assignments.

The latest Kestrel ArtLab review is [the symmetric hull and paired-module build](ArtDirection/Generated/KestrelK017/kestrel-symmetric-mirror-20260926-r1/REVIEW.md). The port half is the master: all three hull LODs were bisected at world Z=0, mirrored and welded along the centerline, then independently unwrapped and transferred from the existing paint. Wings and drives use true reflection with corrected winding and positive transforms. Saved-file checks found no interior-texel UV overlap; all twelve texture hashes and the final FBX were verified before Unity import. Actual imported shape, normals, paired UVs, LOD materials and nine URP captures passed. Fixed-camera silhouette comparisons overlap by at least 99.9886%; paint differences remain. The build is now also registered as a [separate flyable Kestrel prototype](ArtDirection/AUTHORED_SHIP_RUNTIME.md), `SP-K017`, in catalog slot 100. Fourteen live launch, flight, gear, collision and LOD checks passed. The original 100 craft retain their assignments. Existing off-seam hull openings, projection seams, unfinished component surfaces and landing-gear attachment gaps remain visible; the current pressure cabin is temporary.

## Local mesh authoring trial

TripoSG now runs locally on the development GPU. An isolated Kestrel engine reference produced a real mesh in 66.95 seconds using 5.68 GiB of allocated GPU memory. Blender cleanup, three LODs, editable rig and Flight/Landing FBX clips are imported and checked in Unity (`Validation/local-mesh-import.txt`). The asset remains in `Assets/SpacePatriot/ArtLab/KestrelDrive`, outside the live fleet. See [visual findings](ArtDirection/Generated/KestrelDrive/VISUAL_REVIEW.md): crisp mechanical edges, correct rear exhaust, separate moving internals, production materials and collision proxies still need work. This proves the modular asset workflow; it does not complete the visual remake.

The Kestrel K-017 multipart authoring recipe is in `Tools/LocalMeshes/kestrel-kit.json`; `build-kestrel.ps1` runs the local hull, wing and landing-gear generation, reuses the drive nacelle, then assembles and texture-bakes the parts in Blender. The Unity Editor importer keeps its prefab inside the versioned ArtLab folder. The base-color atlas samples the four component concepts only on matching-facing surfaces; other sides receive the hull base finish. Six directional captures of every component and the assembled ship expose view-specific problems, but only the supplied concept views contain projected art. This is a review candidate, not a finished replacement: generated silhouettes, unsupported-side detail, attachment alignment and functional/animated details still require art review and further authoring.

External model contributors can use [MODEL_CONTRIBUTING.md](MODEL_CONTRIBUTING.md) for the coordinate convention, source/export handoff format, and review steps. The committed [comparison board](ArtDirection/Generated/KestrelK017/kestrel-v1/Renders/Comparison/comparison-board.png) captures the current Kestrel baseline; the HTML report contains per-part overlays and color-error maps. Keep new work in `ArtDirection/Contributions/` and submit source plus review renders before an asset is promoted into the Unity ArtLab.

## Inversion and controls correction

The conversion had reflected mesh positions and normals without correcting triangle winding. The importer now reconciles each triangle with its transformed normals and replaces existing mesh data. Validation covers 1,246 unique meshes and 760,862 nondegenerate triangles. The cockpit and imported hull were visually inspected after correction; terminal label orientation was corrected in code.

Keyboard commands no longer wait for every input to return to neutral after focus/menu transitions. Holding Space continues to provide thrust after launch. Landing retains the speed limit instead of setting it to zero. Mouse steering uses direct angular displacement instead of delayed stick-style acceleration; mouse and controller vertical inversion are separate settings.

`Validation/direction-and-launch.txt` records 23 live controller checks using virtual Input System devices. This does not certify every physical controller or full gameplay parity. The original controls/cargo/weapons and progression checks were rerun as well. The historical browser smoke test is retained in Validation/browser-smoke-test.md; it does not validate this revision or the future Windows player.

## Fauna concepts and asset pipeline

`Assets/SpacePatriot/Resources/CreatureRosters.json` and `ArtDirection/Creatures/` contain 190 stable, world-assigned creature entries: ten per each of 19 worlds, with distinct roles, habitat, silhouette, palette, encounter stats, abilities, and six standard views. Ten anatomy-family prefabs are the reusable runtime base, not 190 finished bespoke models. Wildlife actors move around their habitat, selected predators hunt the player, bosses telegraph attacks through Spellworks, hits reduce their health, and defeat awards progression. `Validation/wildlife-rosters.txt` and `Validation/runtime-wildlife.txt` record the catalog and live encounter checks.

The current concept boards cover weapons, flora, fauna, and planetary geology under `ArtDirection/Concepts/`. `ArtDirection/PIPELINE_STANDARD.md` and `Tools/AssetPipeline/creatures/` define the shared Tripo-to-Blender import, scale/origin/axis rules, fixed view cameras, globally packed bake UVs, texture maps, Unity FBX handoff, and repeatable six-view image comparison. The Blender smoke run produced a `.blend`, Unity FBX, base-color/AO/normal maps, and six orthographic review renders. That run used an existing engine mesh as a pipeline test prop; it does not approve that mesh as a weapon or demonstrate final art quality.

Unreal collaborators have a separate [Blueprint handoff repository](https://github.com/xxhendrixx/space-patriot-unreal). It contains the first Blueprint-facing system port and generates Unreal assets locally; it does not replace or claim parity with the Unity project.

## Project delivery decision

Development continues in Unity 6000.3.25f1 with Windows x64 as the target. No installer is included. Desktop build configuration, file-based saves with a backup, F11 display switching and exit controls are prepared for later standalone builds. The editor still uses its existing local save. `Validation/desktop-project.txt` records target configuration and isolated file-save checks; no native build or installer result is claimed.
